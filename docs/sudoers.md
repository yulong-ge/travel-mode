# Optional sudoers rules

Recommended order:

1. Configure nothing. Travel-mode prompts for a password only when a privileged Action needs it.
2. If desired, choose the **pmset** scope. This grants every pmset argument, including factory resets; it is not a restriction to the current profile keys.
3. **all is not recommended**. It also grants arbitrary system daemon loading/unloading, root TERM signals, Spotlight and Wi-Fi control. Loading a daemon can execute arbitrary code as root.

## Preview, install and remove

```bash
travel-mode sudoers print
travel-mode sudoers print --scope all --user example_user
travel-mode sudoers install --dry-run
travel-mode sudoers install
travel-mode sudoers status
travel-mode sudoers status --json
travel-mode sudoers uninstall
```

`print --user` accepts a conservative ASCII account name and quotes it as a literal; whitespace, sudoers syntax and reserved ALL are rejected. Installation always targets the invoking UID's account, not an environment-supplied USER or an alternate `--user`. It requires stdin and stdout to be terminals. It writes a temporary fragment, runs `/usr/sbin/visudo -c -f <temporary-file>` as the current user, shows the path and complete content, then requires the literal `yes`. If unprivileged visudo cannot validate the file, installation stops; it does not silently elevate validation.

Only after confirmation does the Action/Executor invoke `/usr/bin/sudo /usr/bin/install -m 0440 -o root -g wheel <temporary-file> /etc/sudoers.d/travel-mode`. The user may receive one password prompt. Existing files are refused unless `--force` is supplied and the user types a second `yes`; symlinks and directories are always refused. Uninstall confirms before running `/usr/bin/sudo /bin/rm /etc/sudoers.d/travel-mode`. These administrative commands are not included in generated passwordless rules. No command manages `/etc/sudoers.d/travel-mode-test` or any other policy file.

Dry-run prints planned validation/installation/removal commands without changing the policy or requesting a password; it does not claim that the policy was validated or installed. A syntax check validates only the fragment, not the effective complete sudo configuration. Status reads the installed fragment and issues noninteractive `sudo -n -l` probes for the operational catalog. If root-only file permissions prevent reading, it attempts only `sudo -n /bin/cat /etc/sudoers.d/travel-mode`; failure is reported explicitly, without a password prompt. A list-mode permission probe is not a guarantee that a later command can run without authentication or that its target exists.

## Generated examples

`example_user` is a placeholder account. System paths and operational rules come from `privileges.py`, also used by the real executable resolver. Policy-management tools are pinned separately and are deliberately excluded from these scopes.

### pmset (default)

```sudoers
# Generated by travel-mode. Optional; ordinary password prompts require no rule.
# pmset scope: authorizes all pmset arguments, not only travel-mode settings.
# Allows every pmset operation, including disruptive power changes and factory resets.
"example_user" ALL=(root) NOPASSWD: /usr/bin/pmset
```

### all (not recommended)

```sudoers
# Generated by travel-mode. Optional; ordinary password prompts require no rule.
# all scope is not recommended. load/unload/PID globs are broad; root code execution is possible. Administrative sudoers editing is not authorized.
# Allows every pmset operation, including disruptive power changes and factory resets.
"example_user" ALL=(root) NOPASSWD: /usr/bin/pmset
# Allows reading system daemon labels and PIDs.
"example_user" ALL=(root) NOPASSWD: /bin/launchctl list
# Allows loading arbitrary system daemons, which can execute code as root; not recommended.
"example_user" ALL=(root) NOPASSWD: /bin/launchctl load *
# Allows unloading arbitrary system daemons and interrupting their work.
"example_user" ALL=(root) NOPASSWD: /bin/launchctl unload *
# Allows starting or stopping Spotlight indexing for the root volume.
"example_user" ALL=(root) NOPASSWD: /usr/bin/mdutil -i on /
# Allows starting or stopping Spotlight indexing for the root volume.
"example_user" ALL=(root) NOPASSWD: /usr/bin/mdutil -i off /
# Allows enabling/disabling Wi-Fi interfaces. Argument globs span whitespace; these rules do not enforce the product guard.
"example_user" ALL=(root) NOPASSWD: /usr/sbin/networksetup -setairportpower * on
# Allows enabling/disabling Wi-Fi interfaces. Argument globs span whitespace; these rules do not enforce the product guard.
"example_user" ALL=(root) NOPASSWD: /usr/sbin/networksetup -setairportpower * off
# Allows sending TERM to arbitrary PIDs as root, not only configured apps.
"example_user" ALL=(root) NOPASSWD: /bin/kill -TERM *
```

Sudoers `*` matches the concatenated argument string, including whitespace; it does not enforce one path, one interface or one PID. These permissions exceed the product's exact process-identity/plist checks. Do not use `NOPASSWD: ALL`. Prefer exact site-specific argv rules covering both apply and captured restore values if you maintain your own policy. No root permission is required for ordinary user LaunchAgent unload/reload. System daemon actions still use load/unload; the tool never uses launchctl disable.

## 中文说明

建议顺序为不配置（需要时输入密码）→ pmset 范围 → all 范围。pmset 范围允许所有 pmset 参数，包括恢复出厂设置。all 不推荐：其中任意系统 daemon 的加载可执行 root 代码；卸载可中断系统服务，TERM 可发送到任意 PID，索引与 Wi-Fi 也会受影响。参数通配符可跨空白匹配，规则本身不执行产品守卫。

`print` 可指定经过校验的示例用户名；`install` 只授权当前 UID 的账号。安装先写临时片段、以当前用户运行 visudo 只读校验、显示完整内容，再要求输入 yes。校验失败则停止，不自动提权校验。已有文件需要 --force 和第二次 yes；符号链接与目录始终拒绝。安装/卸载都需要交互终端，只管理 /etc/sudoers.d/travel-mode，不碰维护者的 travel-mode-test。状态查询不提示密码；内容无法读取或权限探测失败会明确显示。--dry-run 只预览，不声称已校验或安装。生成的规则不包含策略安装、删除或读取操作的免密权限。
